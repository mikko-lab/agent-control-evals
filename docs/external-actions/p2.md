# P2: network routes and target aliases

Status: live adapter implemented; the [review record](p2-review.md) records validation and the final review decision. The original component-only evidence is preserved separately.
Baseline: `4aab6178c72d24e6980b452101be132546ae88e3` (remote main verified 2026-11-17).

## Decisions made before implementation

- Keep P1a/P1b code, schemas, corpus, profiles, pins and reports unchanged. Add a separate P2 component profile and versioned report. No commercial logic or external SUT integration.
- Use the actual Node WHATWG URL parser. Address forms: canonical IPv4, hexadecimal IPv4, canonical hostname, a distinct alias, trailing dot and uppercase. Each has a matching allowed P control; Q is forbidden. These exercise IP-vs-name, parser numeric normalization, resolver mapping, terminal-dot removal and case normalization respectively.
- IPv6 (including mapped IPv6), IDN, redirects/shorteners, browser/shell routes and DNS rebinding/check-use changes remain out of scope. P1b disables IPv6; do not silently weaken that isolation.
- A deterministic resolver double maps only named `.test` names to the two synthetic addresses, has explicit NXDOMAIN, and never invokes OS DNS. It models resolution, not a DNS wire protocol. A changed static answer is a separate case, not rebinding.
- A proxy double accepts one explicit final target and sends only to a resolved P/Q endpoint through an injected transport. No recursive proxying, environment proxies, redirects, credentials or arbitrary destinations. The guard must authorize the final target. The proxy deliberately does not duplicate guard authorization, so bypass mutants remain observable.
- Granted authority is P/submit; the scenario declares final recipient independently of guard output. P1's specification-only oracle derives expected decisions and connection/request/stored-submission effects before execution. Missing resolution has a DENY/no-effect expectation.
- Component tests execute guard/parser/resolver/proxy logic but use an in-memory transport and synthetic P1 observation builder. They are **not** independent recipient or network-isolation evidence. The report must label this and must never grant P2 acceptance.
- Integration must use distinct E/D/H identities, closed network namespaces, P/Q-only recipient egress and explicit proxy/resolver edges, no external DNS or default routes, protected H observation channels, pre/post configuration comparison, canary/drop-counter checks and bounded executor/recipient closure. Check the proxy/resolver namespaces too. A setup failure is HARNESS_ERROR; incomplete closure is never PASS. No host-network fallback.
- A live proxy requires its own journal, tracker and closure treatment plus attribution for both hops; the existing P1b per-attempt source-IP model cannot simply be asserted across a proxy. Do not hide that extension inside P1b. No production isolation or arbitrary malicious in-process guard guarantee is claimed.

## Live execution and recorded evaluation

The dedicated images install tools only into a disposable container. No existing server is used. Run one scenario topology at a time. Node 22 and 24, root for setup, iproute2, iptables, util-linux, and namespace/mount permissions are required. P2 does not require writable cgroups; P1b regressions additionally require a private writable cgroup v2 subtree with `cgroup.kill` and `tc netem`.

```sh
docker build -f scripts/p2.Dockerfile -t ace-p2-linux:node22 .
docker build --build-arg NODE_VERSION=24 -f scripts/p2.Dockerfile -t ace-p2-linux:node24 .
node scripts/p2-matrix.cjs out/p2-build-NEW out/p2-matrix-NEW

# Offline only, no socket creation:
node out/p2-build-NEW/src/external-actions/p2/live-cli.js evaluate \
  out/p2-matrix-NEW/node22-reference-1/raw.json out/p2-replay-NEW
```

The matrix script records exact image IDs, commands, exits and raw hashes, runs three baselines and five named guard mutants on each version, and runs the five technical injections separately. Each container has `--network none`, a read-only repository mount and an evidence-only writable mount. Only NET_ADMIN and SYS_ADMIN are added for internal namespace setup; no Docker socket or host-network mount is supplied. `/proc/sys` remounts are confined to a private mount namespace attached to each newly created network namespace.

The raw format is `external-action-p2-live-run/1`, the evaluated live format is `external-action-p2-live-report/1`, and the strengthened component format is `external-action-p2-component-report/2`. See the [raw schema](../../schemas/external-actions/p2-live-run-1.schema.json) and [report schema](../../schemas/external-actions/p2-report-1.schema.json). Unknown versions and missing records fail closed. Offline evaluation checks configured case/attempt/run IDs, event hash chains, exact topology rules, protected channels, natural process exit/drain, each proxy hop, resolver records and P/Q stored content. It never derives receipt from the guard's decision or from proxy acknowledgements.

Single-run reports and the matrix runner keep `p2_acceptance: false`: neither alone includes the required whole-suite/P1 regression evidence. The separate review record states the reviewed scope; neither a single run nor the matrix grants overall P2 acceptance. No schema or hash proves authenticity: the root collector, service code and Linux kernel remain trusted. There is no claim of isolation against arbitrary malicious in-process guard code.

The clean-build provenance records source and compiled hashes, config/lock hashes, build command, Node/TypeScript versions, HEAD and dirty status. It refuses reused output directories and detects changed source/compiled bytes before scenario execution. The original report's claim of six initial source modules was a counting error: that milestone had **five** P2 source modules. Current counts are generated from the provenance manifest.

The historical channel-writable run lacks structured permission-change diagnostics and is rejected by the new gate. A new diagnostic run is required; it must not be fabricated from the old boolean or error text. Matrix inputs bind exact paths and SHA-256 hashes; relocated packages require explicit path rebinding without changing file hashes. The collector and the initial bindings remain trusted.

Historical reports and raw bundles are retained separately, not GitHub-hosted by this commit. See [evidence availability and relocation](p2-evidence-access.md) before using historical-import or offline commands. A clean Git checkout is required by the provenance build script; a source tar without Git metadata alone does not provide HEAD provenance.
